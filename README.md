# Эмулятор командной оболочки

Практическая работа по дисциплине «Конфигурационное управление».

**Вариант №22.**

## Общее описание

Проект представляет собой консольный эмулятор UNIX-подобной командной оболочки, разработанный на Python.

Программа поддерживает интерактивный режим, параметры командной строки, выполнение стартовых скриптов и загрузку виртуальной файловой системы (VFS) в оперативную память.

Выполненные этапы:

- Этап 1. REPL.
- Этап 2. Конфигурация.
- Этап 3. Виртуальная файловая система.

## Этап 1. REPL

Реализован минимальный консольный интерфейс с приглашением к вводу, содержащим имя VFS.

Поддерживаемые команды:

- `ls` — заглушка, выводящая имя команды и аргументы.
- `cd` — заглушка, принимающая один аргумент.
- `exit` — завершение работы эмулятора.

Реализованы разбор пользовательского ввода по пробелам и обработка неизвестных команд и неверных аргументов.

## Этап 2. Конфигурация

Добавлена возможность настройки эмулятора через параметры командной строки:

- `--vfs` — путь к виртуальной файловой системе.
- `--script` — путь к стартовому скрипту.

При запуске программа выводит переданные параметры.

Реализовано выполнение команд из текстового стартового скрипта с отображением ввода и вывода. При первой ошибке выполнение прекращается и выводится номер строки. Проверяется существование файла стартового скрипта.

Для тестирования подготовлены три `.bat`-файла в папке `tests`.

## Этап 3. Виртуальная файловая система (VFS)

### Описание

Реализована загрузка виртуальной файловой системы из обычной директории на диске пользователя.

Функция `load_vfs()` проверяет указанный путь и загружает содержимое директории в оперативную память.

Загрузка выполняется рекурсивно с сохранением структуры всех вложенных папок и файлов.

Если параметр `--vfs` не указан, создаётся пустая VFS в оперативной памяти.

### Представление данных

Виртуальная файловая система представлена вложенными словарями Python.

Для каждого объекта сохраняются его тип и владелец. Для директорий дополнительно хранится словарь вложенных элементов, для файлов — их содержимое.

Содержимое файлов считывается в виде байтов с помощью `read_bytes()`, что позволяет загружать как текстовые, так и двоичные файлы.

Все операции с загруженной VFS выполняются в оперативной памяти. Изменение виртуальных файлов не затрагивает исходные данные на диске.

Символические ссылки не поддерживаются.

### Обработка ошибок

При загрузке VFS предусмотрена обработка следующих ситуаций:

- Указанная директория не существует.
- Вместо директории указан файл.
- Отсутствует доступ к файлам или папкам.
- Обнаружен неподдерживаемый тип объекта.

При возникновении ошибки программа выводит соответствующее сообщение и завершается с ненулевым кодом.

### Тестовые файловые системы

Для проверки загрузчика созданы три варианта VFS в папке `tests/vfs`.

**1. Минимальная VFS — `minimal`**

Содержит один текстовый файл `hello.txt`. Используется для проверки базовой загрузки файлов.

**2. VFS с несколькими файлами — `multiple`**

Содержит два файла в корневой директории и вложенную папку `docs` с файлом `info.txt`.

Позволяет проверить чтение нескольких файлов и обработку вложенных директорий.

**3. Многоуровневая VFS — `nested`**

Содержит файл `root.txt` и три уровня вложенности:

`level1/level2/level3/deep.txt`

Используется для проверки рекурсивной загрузки файловой системы и чтения содержимого глубоко вложенных файлов.

### Запуск программы

Отдельная сборка не требуется. Необходим установленный Python 3.

Обычный запуск из корня проекта:

`.\run.bat`

Запуск с минимальной VFS:

`.\run.bat --vfs tests\vfs\minimal`

Запуск с несколькими файлами:

`.\run.bat --vfs tests\vfs\multiple`

Запуск с многоуровневой VFS:

`.\run.bat --vfs tests\vfs\nested`

Запуск VFS со стартовым скриптом:

`.\run.bat --vfs tests\vfs\nested --script tests\stage3_nested.txt`

При успешной загрузке выводятся сообщение о загрузке VFS и количество элементов в её корневой директории.

Команды `ls` и `cd` на данном этапе остаются заглушками. Их полноценная работа с виртуальной файловой системой будет реализована на четвёртом этапе.

### Тестирование

Для автоматического тестирования используются `unittest` и Windows-скрипты `.bat`.

Запуск всех Python-тестов:

`py -m unittest discover -s tests -v`

Тесты проверяют:

- Загрузку минимальной VFS.
- Загрузку VFS с несколькими файлами.
- Загрузку трёхуровневой файловой системы.
- Обработку отсутствующей директории.
- Обработку файла, переданного вместо директории.
- Чтение двоичных данных.
- Независимость данных VFS от исходных файлов на диске.

Для проверки работы программы созданы дополнительные Windows-скрипты:

- `test_vfs_minimal.bat` — минимальная VFS.
- `test_vfs_multiple.bat` — VFS с несколькими файлами.
- `test_vfs_nested.bat` — три уровня вложенности.
- `test_vfs_errors.bat` — проверка обработки ошибок.

Запуск:

`.\tests\test_vfs_minimal.bat`

`.\tests\test_vfs_multiple.bat`

`.\tests\test_vfs_nested.bat`

`.\tests\test_vfs_errors.bat`

Тесты предыдущих этапов также сохранены для проверки обратной совместимости.

## Структура проекта

- `src/main.py` — основной код эмулятора.
- `src/vfs.py` — загрузчик виртуальной файловой системы.
- `tests/test_main.py` — тесты первого этапа.
- `tests/test_vfs.py` — автоматические тесты VFS.
- `tests/vfs/` — тестовые файловые системы.
- `tests/*.txt` — стартовые скрипты.
- `tests/*.bat` — Windows-скрипты тестирования.
- `run.bat` — запуск программы.
- `.gitignore` — исключения для Git.
- `README.md` — документация проекта.
