# Эмулятор командной оболочки

Практическая работа по дисциплине «Конфигурационное управление».

**Вариант №22.**

## Общее описание

Проект представляет собой консольный эмулятор UNIX-подобной
командной оболочки, разработанный на Python.

Программа поддерживает интерактивный режим, параметры командной
строки, выполнение стартовых скриптов, виртуальную файловую систему
(VFS) и основные команды командной оболочки.

Выполненные этапы:

- Этап 1. REPL.
- Этап 2. Конфигурация.
- Этап 3. Виртуальная файловая система.
- Этап 4. Основные команды.

## Этап 1. REPL

На первом этапе реализован минимальный консольный интерфейс.

Добавлены:

- приглашение к вводу с именем VFS;
- разбор команды и аргументов по пробелам;
- команды-заглушки `ls` и `cd`;
- команда `exit`;
- обработка неизвестных команд;
- обработка неверных аргументов.

Эмулятор работает в цикле до выполнения команды `exit`.

## Этап 2. Конфигурация

Добавлены параметры командной строки:

- `--vfs` — путь к виртуальной файловой системе;
- `--script` — путь к стартовому скрипту.

При запуске программа выводит переданные параметры.

Реализовано выполнение команд из стартового скрипта.
Команды и результаты их выполнения отображаются на экране.

При первой ошибке выполнение скрипта прекращается и выводится
номер строки, в которой произошла ошибка.

Для тестирования используются Windows-скрипты `.bat` из папки
`tests`.

## Этап 3. Виртуальная файловая система

Реализована загрузка VFS из обычной директории на диске пользователя.

Файловая система рекурсивно считывается в оперативную память
и представляется вложенными словарями Python.

Для файлов сохраняется их содержимое в виде байтов, поэтому
поддерживаются как текстовые, так и двоичные данные.

Исходная файловая система на диске при работе эмулятора
не изменяется.

Обрабатываются ошибки:

- директория VFS не существует;
- вместо директории указан файл;
- невозможно прочитать файл или каталог;
- обнаружен неподдерживаемый тип объекта.

Для тестирования подготовлены три VFS:

- `minimal` — минимальная файловая система;
- `multiple` — несколько файлов и каталог;
- `nested` — не менее трёх уровней вложенности.

## Этап 4. Основные команды

На четвёртом этапе реализована полноценная работа основных
команд с виртуальной файловой системой.

Поддерживаются команды:

- `ls`;
- `cd`;
- `date`;
- `clear`;
- `exit`.

### Обработка путей

Для работы с путями используется отдельный модуль
`src/path_utils.py`.

Поддерживаются:

- абсолютные пути;
- относительные пути;
- `.` — текущий каталог;
- `..` — родительский каталог;
- несколько последовательных `..`;
- повторяющиеся разделители;
- прямые и обратные слеши;
- сложные комбинации элементов пути.

Например:

```text
/projects/student/files/../../archive/././docs
```

нормализуется до:

```text
/projects/archive/docs
```

Выход выше корня VFS невозможен.

### Команда cd

Команда `cd` изменяет текущий каталог внутри виртуальной
файловой системы.

Примеры:

```text
cd docs
cd /docs
cd ..
cd ./docs
cd /docs/../docs
```

После успешного перехода изменяется приглашение командной строки.

Например:

```text
my_vfs:/$ cd docs
my_vfs:/docs$
```

При попытке перейти в отсутствующий каталог или в файл
выводится сообщение об ошибке.

### Команда ls

Команда `ls` выводит содержимое каталога VFS.

Обычный запуск:

```text
ls
```

Поддерживаются ключи:

- `-l` — подробный формат вывода;
- `-h` — удобное отображение размера;
- `-a` — отображение скрытых объектов.

Поддерживаются как объединённые, так и раздельные комбинации
ключей:

```text
ls -l
ls -h
ls -a
ls -la
ls -lh
ls -ah
ls -lah
ls -l -a -h
```

Ключи можно использовать вместе с путями:

```text
ls docs
ls ./docs
ls /docs
ls -l /docs
ls -lah /docs
ls /docs/.././docs
```

Без ключа `-a` объекты, имя которых начинается с точки,
не отображаются.

С ключом `-a` отображаются скрытые файлы, а также специальные
элементы `.` и `..`.

Ключ `-l` выводит дополнительную информацию об объекте:

- тип объекта;
- владельца;
- размер;
- имя.

При использовании `-h` вместе с `-l` размер отображается
в удобном для чтения формате.

Неизвестные ключи и неверное количество путей обрабатываются
как ошибки.

### Команда date

Команда `date` выводит текущие дату и время операционной системы.

Пример:

```text
date
```

Пример результата:

```text
2026-10-09 17:34:16 RTZ 2 (зима)
```

Конкретный формат названия часового пояса зависит от настроек
операционной системы.

Команда не принимает аргументы.

### Команда clear

Команда `clear` очищает экран терминала.

Для очистки используется ANSI-последовательность.

Пример:

```text
clear
```

Команда не принимает аргументы.

### Состояние эмулятора

Текущая VFS и текущий каталог сохраняются в состоянии программы.

Используется структура:

```python
state = {
    "vfs": vfs,
    "cwd": []
}
```

`vfs` содержит виртуальную файловую систему, а `cwd` —
текущий путь пользователя внутри неё.

Благодаря этому команды `cd` и `ls` работают с текущим
состоянием файловой системы.

### Стартовые скрипты этапа 4

Для проверки реализованных команд созданы два сценария.

`tests/stage4_success.txt` проверяет:

- `clear`;
- `date`;
- обычный `ls`;
- ключи `-l`, `-h`, `-a`;
- комбинации ключей;
- абсолютные пути;
- относительные пути;
- `.` и `..`;
- сложные пути;
- переходы с помощью `cd`;
- команду `exit`.

`tests/stage4_errors.txt` проверяет остановку стартового
скрипта при первой ошибке.

Для общего запуска используется:

```powershell
.\tests\test_stage4.bat
```

При успешном выполнении выводится:

```text
STAGE 4 TESTS PASSED
```

## Запуск программы

Отдельная сборка проекта не требуется.

Необходим установленный Python 3.

Обычный запуск:

```powershell
.\run.bat
```

Запуск с VFS:

```powershell
.\run.bat --vfs tests\vfs\multiple
```

Запуск со стартовым скриптом:

```powershell
.\run.bat --script tests\start_ok.txt
```

Запуск одновременно с VFS и стартовым скриптом:

```powershell
.\run.bat --vfs tests\vfs\multiple --script tests\stage4_success.txt
```

Программу также можно запустить как Python-модуль:

```powershell
py -m src.main
```

## Тестирование

Для автоматического тестирования используется модуль `unittest`.

Запуск всех Python-тестов:

```powershell
py -m unittest discover -s tests -v
```

Основные тестовые файлы:

- `tests/test_main.py` — базовая логика эмулятора;
- `tests/test_vfs.py` — загрузка виртуальной файловой системы;
- `tests/test_paths.py` — обработка путей;
- `tests/test_cd.py` — команда `cd`;
- `tests/test_ls.py` — команда `ls` и её ключи;
- `tests/test_basic_commands.py` — команды `date` и `clear`.

Тестирование предыдущих этапов:

```powershell
.\tests\test_default.bat
.\tests\test_parameters.bat
.\tests\test_invalid_script.bat
```

Тестирование VFS:

```powershell
.\tests\test_vfs_minimal.bat
.\tests\test_vfs_multiple.bat
.\tests\test_vfs_nested.bat
.\tests\test_vfs_errors.bat
```

Тестирование этапа 4:

```powershell
.\tests\test_stage4.bat
```

Тесты предыдущих этапов сохраняются и используются для проверки
того, что новая функциональность не нарушает уже реализованную.
