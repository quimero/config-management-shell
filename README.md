# Эмулятор командной оболочки

Практическая работа по дисциплине «Конфигурационное управление».

**Вариант №22.**

## Общее описание

Проект представляет собой консольный эмулятор UNIX-подобной
командной оболочки, разработанный на Python.

Программа поддерживает интерактивный режим, параметры командной
строки, выполнение стартовых скриптов, виртуальную файловую систему
(VFS) и основные команды командной оболочки.

Выполненные этапы:

- Этап 1. REPL.
- Этап 2. Конфигурация.
- Этап 3. Виртуальная файловая система.
- Этап 4. Основные команды.
- Этап 5. Дополнительные команды.

## Этап 1. REPL

На первом этапе реализован минимальный консольный интерфейс.

Добавлены:

- приглашение к вводу с именем VFS;
- разбор команды и аргументов по пробелам;
- команды-заглушки `ls` и `cd`;
- команда `exit`;
- обработка неизвестных команд;
- обработка неверных аргументов.

Эмулятор работает в цикле до выполнения команды `exit`.

## Этап 2. Конфигурация

Добавлены параметры командной строки:

- `--vfs` — путь к виртуальной файловой системе;
- `--script` — путь к стартовому скрипту.

При запуске программа выводит переданные параметры.

Реализовано выполнение команд из стартового скрипта.
Команды и результаты их выполнения отображаются на экране.

При первой ошибке выполнение скрипта прекращается и выводится
номер строки, в которой произошла ошибка.

Для тестирования используются Windows-скрипты `.bat` из папки
`tests`.

## Этап 3. Виртуальная файловая система

Реализована загрузка VFS из обычной директории на диске пользователя.

Файловая система рекурсивно считывается в оперативную память
и представляется вложенными словарями Python.

Для файлов сохраняется их содержимое в виде байтов, поэтому
поддерживаются как текстовые, так и двоичные данные.

Исходная файловая система на диске при работе эмулятора
не изменяется.

Для тестирования подготовлены три VFS:

- `minimal` — минимальная файловая система;
- `multiple` — несколько файлов и каталог;
- `nested` — не менее трёх уровней вложенности.

Обрабатываются ошибки загрузки и неверного формата VFS.

## Этап 4. Основные команды

Реализована полноценная работа команд:

- `ls`;
- `cd`;
- `date`;
- `clear`;
- `exit`.

Команда `ls` поддерживает ключи:

- `-l` — подробный формат;
- `-h` — удобное отображение размера;
- `-a` — отображение скрытых объектов;
- комбинации ключей.

Команда `cd` изменяет текущий каталог внутри VFS.

Для обработки путей используется модуль `src/path_utils.py`.

Поддерживаются:

- абсолютные пути;
- относительные пути;
- `.`;
- `..`;
- сложные комбинации элементов пути;
- прямые и обратные слеши.

Текущий каталог хранится в состоянии программы и отображается
в приглашении командной строки.

Команда `date` выводит текущие дату и время, а команда `clear`
очищает экран терминала.

## Этап 5. Дополнительные команды

На пятом этапе реализована команда `chown`.

Команда изменяет владельца файла или каталога внутри виртуальной
файловой системы.

Все изменения выполняются только в оперативной памяти.
Исходные файлы и каталоги на диске не изменяются.

### Команда chown

Формат команды:

```text
chown ВЛАДЕЛЕЦ ПУТЬ
```

Пример:

```text
chown sergey readme.txt
```

После выполнения владелец объекта внутри VFS изменяется:

```text
- sergey     37 readme.txt
```

Команда работает как с файлами, так и с каталогами.

Пример для каталога:

```text
chown admin docs
```

После этого результат можно проверить командой:

```text
ls -l
```

### Работа с путями

Команда `chown` использует общий механизм обработки путей,
реализованный на предыдущем этапе.

Поддерживаются относительные пути:

```text
chown sergey readme.txt
```

Абсолютные пути:

```text
chown student /docs/info.txt
```

Пути относительно текущего каталога:

```text
cd docs
chown teacher info.txt
```

Сложные конструкции с `.` и `..`:

```text
chown user /docs/.././readme.txt
```

Путь сначала нормализуется, после чего объект ищется внутри VFS.

### Изменение только в памяти

После загрузки VFS каждый объект содержит поле `owner`.

Например:

```python
{
    "type": "file",
    "owner": "root",
    "content": b"..."
}
```

Команда `chown` изменяет только значение поля `owner`:

```python
node["owner"] = owner
```

Изменение существует только до завершения работы программы.

Например, если выполнить:

```text
chown sergey readme.txt
```

в текущем сеансе владелец станет `sergey`.

После выхода:

```text
exit
```

и повторной загрузки VFS с диска:

```powershell
.\run.bat --vfs tests\vfs\multiple
```

владелец снова будет:

```text
root
```

Это подтверждает, что исходная файловая система на диске
не модифицируется.

### Обработка ошибок

Команда `chown` требует ровно два аргумента:

```text
chown ВЛАДЕЛЕЦ ПУТЬ
```

При отсутствии аргументов:

```text
chown
```

выводится сообщение:

```text
Ошибка: команда chown ожидает владельца и путь
```

При отсутствии пути:

```text
chown sergey
```

также выводится сообщение об ошибке.

Если указанный объект отсутствует:

```text
chown sergey missing.txt
```

выводится:

```text
Ошибка: путь не найден
```

Ошибки команды также корректно обрабатываются при выполнении
стартового скрипта.

### Автоматические тесты chown

Для команды создан файл:

```text
tests/test_chown.py
```

Тесты проверяют:

- изменение владельца файла;
- изменение владельца каталога;
- абсолютный путь;
- относительный путь;
- сложный путь;
- отсутствие аргументов;
- недостаточное количество аргументов;
- лишние аргументы;
- отсутствующий объект;
- изменение VFS только в оперативной памяти.

Запуск тестов `chown`:

```powershell
py -m unittest discover -s tests -p "test_chown.py" -v
```

Запуск всех Python-тестов:

```powershell
py -m unittest discover -s tests -v
```

### Стартовые скрипты этапа 5

Для проверки этапа созданы два стартовых сценария.

`tests/stage5_success.txt` проверяет успешную работу `chown`:

- изменение владельца файла;
- изменение владельца каталога;
- абсолютные пути;
- относительные пути;
- сложные пути;
- работу после `cd`;
- отображение результата через `ls -l`.

`tests/stage5_errors.txt` проверяет обработку ошибки.

После первой ошибки выполнение стартового скрипта прекращается.

Для автоматического запуска используется:

```powershell
.\tests\test_stage5.bat
```

При успешном прохождении проверки выводится:

```text
STAGE 5 TESTS PASSED
```

## Запуск программы

Отдельная сборка проекта не требуется.

Необходим установленный Python 3.

Обычный запуск:

```powershell
.\run.bat
```

Запуск с VFS:

```powershell
.\run.bat --vfs tests\vfs\multiple
```

Запуск со стартовым скриптом:

```powershell
.\run.bat --script tests\start_ok.txt
```

Запуск с VFS и стартовым скриптом этапа 5:

```powershell
.\run.bat --vfs tests\vfs\multiple --script tests\stage5_success.txt
```

Программу также можно запустить как Python-модуль:

```powershell
py -m src.main
```

## Тестирование

Для автоматического тестирования используется модуль `unittest`.

Запуск всех Python-тестов:

```powershell
py -m unittest discover -s tests -v
```

Основные тестовые файлы:

- `tests/test_main.py` — базовая логика эмулятора;
- `tests/test_vfs.py` — загрузка VFS;
- `tests/test_paths.py` — обработка путей;
- `tests/test_cd.py` — команда `cd`;
- `tests/test_ls.py` — команда `ls`;
- `tests/test_basic_commands.py` — команды `date` и `clear`;
- `tests/test_chown.py` — команда `chown`.

Тестирование предыдущих этапов:

```powershell
.\tests\test_default.bat
.\tests\test_parameters.bat
.\tests\test_invalid_script.bat
```

Тестирование VFS:

```powershell
.\tests\test_vfs_minimal.bat
.\tests\test_vfs_multiple.bat
.\tests\test_vfs_nested.bat
.\tests\test_vfs_errors.bat
```

Тестирование этапа 4:

```powershell

```

```powershell

```

Тесты предыдущих этапов сохраняются для проверки того, что новая
функциональность не нарушает уже реализованную.
